# `Context`

UIアプリケーションの全状態を保持する中央データベースであり、各種パイプライン操作を集約したコア構造体です。

---

## 概要

`Context` はロジックを抱え込んだ複雑な神オブジェクトではなく、役割ごとに分離された複数のストアを束ねるデータベースとして設計されています。
各ストアは、役割ごとに分類された SoA (SoA: Structure of Arrays) と関連関数群を内包し、処理フェーズごとに必要な SoA だけを分割借用によって明示的に受け渡すことで、ゼロコストかつ安全な内部パイプラインを実現しています。

ユーザーに向けては、これらの関数群が `Context` のメソッドとして使いやすく集約・ラップされています。

---

## 重要な制約：スレッドモデル

> **Warning: UIスレッド拘束**
> `Context` はスレッドローカルにバインドされており、**メインスレッド（UIスレッド）でのみアクセス・操作可能**です。
> バックグラウンドスレッド（ワーカースレッド）から直接 `Context` を操作することはできません。

ワーカースレッドから状態を更新したい場合は、クレートが提供する非同期タスク送信機能、または標準のチャネル（`std::sync::mpsc` 等）を経由してUIスレッド側へメッセージを転送してください。

---

## 2つの主な利用シーン

アプリケーション開発において、`Context`（または `&mut Context`）に触れるのは主に以下の2つの場面です。

### 1. メインループ内でのライフサイクル

自前のウィンドウプロシージャやイベントループを回す際、パイプラインの各フェーズを明示的に呼び出します。

- [`inject_action`](Context::inject_action): OSの入力イベントをキューイング
- [`begin_frame`](Context::begin_frame): キューの消化とインタラクション状態の更新
- [`tick_system_frame`](Context::tick_system_frame): アニメーションやタイマーの進行
- [`sync_layout`](Context::sync_layout): 2パスレイアウト計算
- [`update_accessibility`](Context::update_accessibility): AccessKit ツリーの同期

### 2. イベントハンドラ内での要素操作

`on_click_with` などの `_with` 系ハンドラでは、引数 `cx: &mut Context` として渡されます。

- `cx.current()`: イベントを発火させた要素自身を取得
- `cx.query_first::<T>()` / `cx.try_query_first::<T>()`: Tag をキーにして他の要素を探索
- `cx.find_root_entity()`: ルート要素を取得
- `cx.pointer_position()` / `cx.window_last_size()`: 現在のポインタ座標やウィンドウサイズを取得

その他メソッドに関しては [`Context`] のドキュメントを確認してください。

## 内部構造：独立したストア群

`Context` の内部は、パイプラインのステージに対応するいくつかの独立したストアに分割されています。

| カテゴリ               | ストア     | 主な責務・保持データ                                                         |
| :--------------------- | :--------- | :--------------------------------------------------------------------------- |
| **環境・システム**     | `window`   | ウィンドウの情報                                                             |
|                        | `system`   | テキストエンジンやタスク送受信機能                                           |
| **構造・状態**         | `events`   | イベントリスナーやアクティブなインタラクション状態（例: ホバーやフォーカス） |
|                        | `reactive` | シグナルや購読関係、エフェクト                                               |
|                        | `contents` | テキストや入力コンテンツ                                                     |
|                        | `topology` | 全要素の生存期間を管理するプライマリマップや親子関係などの構造情報           |
|                        | `states`   | DnDやリサイズ、スクロール、テキスト選択情報                                  |
| **計算・評価**         | `layouts`  | ベース、現在、解決済みのレイアウト情報                                       |
| **レンダリング・出力** | `renders`  | レイアウトに影響しない描画情報やアニメーション情報                           |
|                        | `outputs`  | 前フレームと現在の絶対座標のキャッシュ                                       |
|                        | `acce`     | AccessKit との通信用ノードツリー                                             |
| **開発支援**           | `debug`    | MichiuInspector 用のログやプロファイリング情報、`Context` のスナップショット |

## 内部アーキテクチャ

Rustにおいて、単一の巨大な構造体（`Context`）のメソッド間で相互に状態を操作しようとすると、`&mut self` による借用競合が発生します。
`michiu_ui` では、以下の3層構造によってゼロコストかつ安全、そしてシンプルにライフサイクルを実行します。

1.  **Store 層**:
    各ストアに関連関数としてロジックを定義します。名前空間を汚染せず、必要なSoAのみを引数として受け取ります。
    全ての引数は所属ストアに応じたプレフィックスを持ち、引数のソート順は厳密に定められています (守るとは言ってない)。
2.  **[`Pipeline`] 層**:
    `Context` の各ストアを個別のフィールドとして分割借用（Split Borrow）し、
    各ストアの関連関数へ必要な順序でディスパッチします。ライフサイクルの全順序はここに集約されます。
3.  **Context 層**:
    各ストアと `Pipeline` の関連関数をラップし、外部に対してシンプルな単一のAPIセットを提供します。

## 低レイヤ操作と脱出ハッチ（`RawContext`）

`Context` のフィールドは通常 `pub(crate)` で保護されていますが、カスタムレンダラーの実装やパイプラインの独自拡張を行う上級者向けに、
内部の各ストアおよび SoA 配列へ直接アクセスするための脱出ハッチとして [`raw_context_mut`](Context::raw_context_mut) を提供しています。

### なぜ `RawContext` を経由するのか？（分割借用の開放）

`&mut Context` のメソッド経由では、Rustの借用チェッカーによって `Context` 全体が排他ロックされてしまいます。
[`RawContext<'a>`] はすべてのストアを個別の `&'a mut Store` フィールドとして公開（`pub`）しているため、
「レイアウトストアと描画ストアを同時に可変借用して別々の処理に渡す」といった高度な分割借用が可能になります。

```rust
use michiu_ui::prelude::*;

let mut context = Context::new();

// 1. 全ストアが個別の可変参照として展開された RawContext を取得
let mut raw = context.raw_context_mut();

// 2. 複数のストアを同時に分割借用して直接操作
// 例: トポロジーとレイアウトの生SoAを同時に取得して低レイヤ処理を行う
let entities: &mut EntitiesSlot = raw.topology.entities_mut();
let basic: &mut BasicLayoutsSecondary = raw.layouts.basic_mut();

custom_low_level_pass(entities, basic);
```

### 主なユースケース

- **カスタムパイプラインの構築**:
  標準の [`Pipeline`] を使わず、独自のタイミングや順序でフレーム処理を再構築したい場合。
- **SoAの直接的な操作**:
  ライブラリの処理をバイパスしSoAを直接書き換える、追加する場合。
- **外部ツール・インスペクターとの直接連携**:
  内部メトリクスやエンティティ配置を直接吸い出して可視化したい場合。なお、ログやスナップショットの取得には [`MichiuInspector`] の使用を推奨します。

> **Warning: 内部整合性の維持**
> 各ストアの `_mut` サフィックスが付いたメソッド（SoAの可変参照取得）は、
> 通常のAPIが保証する依存関係の更新やダーティフラグの管理を完全にバイパスします。
> エンティティIDの不整合やライフサイクルの矛盾を引き起こさないよう、低レイヤの仕様を理解した上で使用してください。
